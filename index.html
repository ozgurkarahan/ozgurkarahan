01 · How people ask

Voice

Voice is becoming the way we talk to agents.

Speaking is faster than typing: customers call voice agents, and developers talk to their coding agents. A voice agent must listen, act, and know when to hand over to a person.

02 · Where people find it

Distribution

An agent nobody finds is an agent nobody uses. Build it once, publish it in Teams and Microsoft 365 Copilot, and keep the same identity and governance behind every channel.

03 · What it knows and can do

Context

An agent is only as good as the company knowledge it can reach.

Bring company knowledge to the agent in three ways: MCP servers for workflows and data in Salesforce, ServiceNow or SAP; knowledge bases; and retrieval (RAG) over documents. Each trades freshness, cost and control differently.

04 · Whose rights it uses

Identity

The agent acts as the person who asked.

Identity runs through every layer. The user's identity travels from the voice to Salesforce or ServiceNow, so each system applies the rules it already has, instead of middleware rebuilding them behind one service account.

05 · Who sets the rules

Governance

Every agent, tool and skill needs an owner and a rule.

Governance applies at every layer: which channels, data and skills each agent gets, where a person must decide, and, for agents that code or browse, a sandbox per session rather than a shared server.
